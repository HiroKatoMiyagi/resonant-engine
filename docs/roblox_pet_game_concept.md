# Build a Biome — 企画書

- **ゲームタイトル**: **Build a Biome**（Roblox 上の実験名）
- **フランチャイズ**: **Bondlings**（生き物の総称。商標の対象）
- **プラットフォーム**: Roblox（Luau / Roblox Studio）
- **ジャンル**: 巣づくり（環境構築）× 仮想ペット育成 × 放置進行
- **作成日**: 2026-09-05
- **ステータス**: **確定** — Phase 0 着手可

> 名称の三層構造は **§9**、用語の定義は **付録A** にある。
> 言葉に引っかかったら参照のこと。

---

## この企画を三行で

1. プレイヤーが**巣をつくる**と、その環境に応じた卵が現れる。**環境が「何が生まれるか」を決める。**
2. 生まれたペットを**世話する**と、育て方に応じて姿が分かれる。**世話が「どう育つか」を決める。**
3. 育ったペットが素材を採り、それでまた新しい環境をつくれる。**輪が閉じている。**

既存のペット系ゲームでは、ペットは抽選で決まる戦利品でしかない。
本作はその二点を**プレイヤーの行動の結果**に変える。それが唯一の差別化であり、
これ以外の要素は増やさない。

---

## 1. なぜこの設計なのか

### 1.1 市場の前提

Roblox の収益は極端な上位集中である。ごく少数のヒットが支出の大半を占め、
大多数のゲームはほとんど稼げない。「良いものをつくれば売れる」市場ではない。
この前提の上で、勝ち筋のあるジャンルを選ぶ必要がある。

| ジャンル | 評価 | 理由 |
|---|---|---|
| **ペット育成** | ◎ 採用 | Adopt Me!（累計370億訪問）等により7年以上にわたり需要が実証されている常緑ジャンル。卵の孵化は最も実績のある課金導線であり、ペットはトレード可能なため経済が自走する |
| 農場シミュレーター | △ | 需要は本物だが2025年に単一の巨大ヒットが出た後で、後発クローンが数百単位で氾濫済み。波が引いた後の砂浜 |
| 都市建設（大規模シム） | ✕ | Roblox 上位に前例がない。主要年齢層に長時間の戦略的計画が刺さらず、多数エンティティの処理はサーバー予算的にも厳しい |

ただしペット育成も飽和している。**同じものを出しても埋没する。**
そこで必要なのが §1.3 の差別化である。

### 1.2 外殻はすでに定番化している（前提の確認）

差別化を語る前に、**本作の外側の構造には既に多数の先行実装がある**ことを
正確に把握しておく必要がある。

`Hatch a X` 系の名前空間には少なくとも以下が稼働している。

| ゲーム名 | ID |
|---|---|
| Hatch A Pet | 121694347343435 |
| Hatch a Pet! | 89894124382594 |
| Hatch Your Pet | 125442419106134 |
| Hatch an Egg | 125577352565486 |
| Break a Pet Egg! | 84415796795085 |
| Pet Hatchers（1090万訪問・2023年〜） | 12768405553 |

これらの典型的なループは次の通りで、**§3.1 のコアループの外側と一致する**。

> 卵を買う → 自分の敷地に置く → オフライン中も孵化が進む → 孵化 →
> ペットが継続的に収益を生む →
> 敷地に「テーマ」を適用すると、テーマに応じた数値バフがつく

先行作の用語と、本作での対応は次の通り。

| 先行作の用語 | 意味 | 本作での対応 |
|---|---|---|
| プロット（plot） | プレイヤー1人に割り当てられる専用の敷地 | **巣エリア**（§4.3） |
| テーマ（theme） | 敷地全体の見た目を一括で切り替える着せ替え（溶岩調・氷雪調 等） | 該当なし。本作は**設置物を1つずつ置く** |
| バフ（buff） | 収益や採取量に対する数値ボーナス | 該当なし。本作の環境は数値ではなく**出現する種**を変える |

この事実から2つの帰結が出る。

**1. 卵・孵化系のキーワードは取りに行かない**
検索語としての `hatch` `egg` は既に大規模タイトルに所有されている。
新規参入がそこで戦うと、獲得した流入がそのまま競合の下位表示に消える。
名前もサムネイルも、卵ではなく**巣（環境）を主役にする**。

**2. 差別化は30秒以内に外から見えなければならない**
外殻が同じである以上、プレイヤーは即座に「またこれか」と判断する。
中に差別化があっても、見えなければ存在しないのと同じである。

### 1.3 差別化の一点

既存タイトルでは、ペットは**抽選で決まる静的な戦利品**である。
レアリティは乱数が決め、プレイヤーの行動は結果に影響しない。

本作はペットの**種と最終形態の双方を、プレイヤーの行動の関数**とする。

| 軸 | 決定するもの | プレイヤーの行為 |
|---|---|---|
| **環境軸** | 何が生まれるか（種） | 巣をつくる |
| **育成軸** | どう育つか（進化先） | 世話をする |

2軸が掛け合わさることで、組み合わせは線ではなく面になる。

### 1.4 先行実装との差（最重要）

先行作にも「自分の敷地に手を入れる」要素はある。ただしそれは
**敷地全体のテーマを切り替える着せ替え**であり、得られるのは**数値バフ**にとどまる。
同じペットが少し多く稼ぐだけで、**生まれてくるものは変わらない**。

本作は**個々の設置物を自分で置き**、その組み合わせから算出される環境属性が
**何が生まれるかそのもの**を決める。

| 比較項目 | 先行の Hatch 系 | 本作 |
|---|---|---|
| 卵を買う → 放置で孵化 | ○ | ○ |
| ペットが収益を生む | ○ | ○ |
| **敷地に手を入れる方法** | テーマを選んで一括適用（着せ替え） | 設置物を1つずつ置く（§4） |
| **手を入れた結果** | **程度が変わる**（採取量 +10% 等） | **正体が変わる**（生まれる種そのものが変わる） |
| 世話の質で進化先が分岐 | ✕ | ◎ |
| 相反進化 | ✕ | ◎ |

程度差ではなく種類の差である。ここだけが本作の存在理由であり、
**この一点が体感として成立しなければ、本作は先行作の劣化版になる。**
§12 の Phase 0 が検証項目を1点に絞っているのは、この理由による。

### 1.5 この差別化が生むもの

| 効果 | 内容 |
|---|---|
| 唯一性 | 種と進化の二重分岐により「自分だけの一匹」が構造的に生まれる |
| 見せびらかし価値 | ペットと**巣**の二つの自慢対象。巣のスクリーンショットはRobloxで最も拡散力が強い |
| トレード価値 | 希少性が乱数ではなく**環境づくりと手間**に由来するため、価値が安定する |
| 継続動機 | 理想の環境も理想の進化も、一日では到達できない |
| 攻略文化 | 環境と出現種の対応関係がコミュニティの研究テーマになり、Wiki・動画が自然発生する |

### 1.6 テーマ

2つの機構は「**プレイヤーの選択が生命を形作る**」という単一のテーマに収束する。
機能を足したのではなく、テーマを二方向から支えている。

> **あなたがつくった環境が、生まれる命を決める。**
> **あなたの育て方が、その子の未来を決める。**

## 2. ターゲット

| 項目 | 内容 |
|---|---|
| 主要層 | 8〜16歳（Roblox のコア層） |
| 副次層 | 17〜24歳（コレクション／トレード経済の担い手） |
| 地域 | グローバル（UI英語ベース、日本語ローカライズは第2段階） |
| プレイスタイル | 1日2回・各5〜10分の短時間セッション＋放置 |

**自分の場所を持ち、少しずつ手を入れて育てていく遊び**は、この年齢層と相性が極めて良い。
Bloxburg（累計80億訪問超）が示す通り、最も定着率の高い遊びの一つである。

短時間セッションが前提であることは、以降の設計すべてを制約する。
**世話も巣づくりも、長時間の拘束を要求してはならない。**

## 3. 全体構造

### 3.1 コアループ

```
ペットが素材を採集（放置中も進行）
   ↓
巣をつくる → 環境属性が変化
   ↓
属性に応じた卵が出現
   ↓
孵化：環境が「種」を決める
   ↓
育成：環境がケアのベースラインを供給し（受動）
      プレイヤーの世話がそれを押し上げる（能動）
   ↓
両者の組み合わせが「進化」を決める
   ↓
育ったペットがより良い素材を採る
   ↓
より特殊な環境がつくれる ──→ 最初に戻る
```

**閉じた自己強化ループ**である。巣づくりとペット育成が相互に資源を供給し合うため、
どちらか一方だけを遊ぶことができない。

### 3.2 ループの入口：最初の一匹

コアループは輪であるため、**どこから始まるかを別に定義する必要がある**。

最初の一匹を「抽選」や「メニューからの選択」で与えてはならない。
どちらもプレイヤーに**間違った第一印象**を教えてしまう。

| 与え方 | プレイヤーが学ぶこと | 判定 |
|---|---|---|
| 抽選で1匹配る | 「ペットは運で決まる」 | ✕ §1.3 の主張と正反対 |
| メニューから選ばせる | 「ペットはメニューから選ぶもの」 | ✕ 環境の存在を教えられない |
| **小さな巣づくりをさせる** | **「置いたもので、生まれるものが変わる」** | **◎ 採用** |

**採用する導入（最初の3分）**

1. 起動すると、空の巣エリアと、無料の卵が1つ置かれている
2. 素材が2種類だけ渡される（例：温かい石／湿った苔）
3. どちらを置くかで、属性メーターが目の前で動く
4. 置いた環境に応じて、卵から違う子が孵る
5. 「置くもので変わるのか」— **ここが掴み**

**設計上の制約**

| 制約 | 理由 |
|---|---|
| 最初の卵は無料で与える | 課金や通貨の説明を挟むと、掴みまでの距離が伸びる |
| 素材は2種類だけに絞る | 選択肢が多いと因果が見えない。2択なら結果の違いが直感で分かる |
| どちらを選んでも失敗にしない | 両方とも魅力的な子が孵る。§7.2「選択肢を奪わない」と整合 |
| 属性メーターを最初から見せる | 因果を可視化する。結果がランダムに感じられなくなる（§4.2） |
| 孵化後に「違う環境なら違う子が生まれる」と明示する | 2周目への導線。ここで初めてループが閉じる |

この導入は §1.2 の「差別化は30秒以内に外から見えなければならない」への
直接の回答でもある。**チュートリアルそのものが差別化の実演になっている。**

### 3.3 巣は使い捨てにしない

設計上の重要な決定を先に述べる。**巣は孵化のための通過点ではなく、
孵化後も育成に効き続ける生息環境である。**

巣を孵化装置にしてしまうと、孵化した瞬間にプレイヤーがつくり込んだものの
役目が終わり、以後はただの置物になる。巣を育てる遊びを持つゲームとして、
これは致命的な損失になる。

| 時期 | 同じ巣エリアの役割 |
|---|---|
| 孵化前 | 環境属性が**出現する種**を決める（§4） |
| 孵化後 | 環境が**ケアのベースライン**を継続供給する（§5） |

一つの巣エリアを時間軸で二役に使うため、「孵化用の環境」と「育成用の環境」を
別々に持つ必要がない。仕組みが増えるのではなく、統合されて減っている。

なお「巣が家であり、そこで家族や血統が形成される」という発展形については、
**§14.1 に将来の拡張候補として記録した。現時点の設計には含まない。**

### 3.4 時間軸での3層

| 層 | 周期 | 行動 |
|---|---|---|
| Micro | 30秒〜2分 | 世話の行動、設置物を置く、即時フィードバック |
| Meso | 1日 | 孵化、進化判定、デイリー任務、放置収益の回収 |
| Macro | 1週間〜 | 環境のつくり込み、レア種の発見、進化ツリー踏破、トレード、図鑑完成 |

## 4. 巣づくり

### 4.1 設計課題

巣づくりの自由度と、判定の一貫性。この2つは単純に実装すると両立しない。

| 単純な実装 | 失敗の形 |
|---|---|
| 設置物の配置を厳密に読む | 48時間でWikiに正解が載り、全員が同一の「最適な巣」をつくる。自由度が死ぬ |
| 曖昧に読む | 何を置いても結果が変わらないと感じられ、巣づくりが無意味になる |

### 4.2 解法：環境属性ベクトル

**個々の設置物を読まず、置かれた素材から算出される属性値の組み合わせを読む。**

| 属性 | 上げる素材の例 |
|---|---|
| **Heat**（熱） | 溶岩石、炎の結晶、温泉 |
| **Humidity**（湿度） | 水場、苔、霧 |
| **Light**（光） | 発光体、開けた天井 |
| **Nature**（自然） | 草木、花、土 |
| **Mineral**（鉱物） | 岩、鉱石、金属 |
| **Space**（広さ） | 空間の体積、配置密度 |

```
出現卵プール = f(Heat, Humidity, Light, Nature, Mineral, Space)
```

この方式なら、**攻略情報の存在と、自分だけの巣であることが両立する。**

- 巣をつくっている最中に属性メーターがリアルタイムで変動する
  → 因果が可視化され、結果がランダムに感じられない
- 同一の属性値に到達するつくり方が無数に存在する
  → Wikiが「高Heat × 低Humidity」と示しても、見た目の自由は残る
- バイオーム生成（温度・湿度ノイズ）や生き物の孵化条件で広く使われている実証済みのパターン

### 4.3 スコープ制約（最重要）

この層は制約を設けないと開発規模を3倍にする。巣づくり・育成・放置・トレードは
本来3本のゲームであり、企画倒れの最頻出パターンがこれである。**以下を明示的に切る。**

| 切るもの | 理由 |
|---|---|
| 自由変形のボクセル地形 | データ量・パート数・複製コストが許容範囲を超える |
| 採掘・サバイバル・戦闘 | 別ジャンル。ペット育成の焦点が消失する |
| 無限ワールド | DataStore の容量制限（1キー約4MB）に収まらない |

**採用する形式：固定サイズの「巣エリア」へのスナップ配置**

- グリッドサイズ：24×24（Phase 1）／拡張可能
- 設置物：地形タイル＋装飾物（すべて事前定義アセット）
- Bloxburg / Islands と同方式。データ量が上限内に収まり、パート数も制御可能
- 「自分でつくっている」という手応えは十分に得られる
- **巣エリアの拡張はそのまま強力な Game Pass になる**

## 5. 育成

### 5.1 ケアの二層モデル

育成は「プレイヤーが直接おこなう能動ケア」と「環境による受動ケア」の
**二層で構成する**。両者は対立する選択肢ではなく、役割が異なる。

| 層 | 仕組み | 性質 | 提供するもの |
|---|---|---|---|
| **能動ケア** | プレイヤーの直接行動 | 離散・即時・意図的 | 精度、愛着、毎日戻る理由 |
| **環境ケア** | 生息環境が継続供給 | 連続・自動・設計的 | 基礎値の底上げ、放置耐性、つくり込みの報酬 |

### 5.2 結合方式：ベースラインとピーク

環境ケアを単純な「ボーナス加算」にしてはならない。それでは環境がただの数値上乗せとなり、
巣づくりの面白さが失われる。**役割そのものを分離する。**

```
環境ケア = 各ケア軸の「ベースライン（均衡点）」を決定する
能動ケア = ベースラインから一時的に押し上げる

各軸は時間とともにベースラインへ向かって戻っていく（＝ドリフト）
進化判定は「実測値の累積」でおこなう
```

この方式が4つの性質を同時に生む。

| # | 性質 | 効果 |
|---|---|---|
| 1 | 良い環境なら放置しても崩れない | 低頻度・無課金プレイヤーが救われる。§7.2 の健全性原則と整合 |
| 2 | 最高到達点には能動ケアが必要 | ベースラインは均衡点であって天井ではない。ヘビー層に上が残る |
| 3 | 環境で「育ちやすい方向」を設計できる | 静かで暗い巣は Rest が高止まりし、自然に Titan 系へ寄る。**狙った系統のための環境設計**という遊びが生まれる |
| 4 | 環境に逆らう育て方ができる | §5.5 の相反進化 |

### 5.3 ケアパラメータ（4軸）

| 軸 | 能動ケア | 環境ケア（ベースラインを上げる設置物） | 系統への影響 |
|---|---|---|---|
| **Nourish**（栄養） | 餌を手渡す・特殊フード | 餌箱、実のなる木 | 体格・耐久 |
| **Play**（遊び） | 一緒に遊ぶ・散歩 | 遊具、広い空間 | 俊敏・活発さ |
| **Rest**（休息） | 寝かしつける | 寝床、遮光、静かな配置 | 落ち着き・特殊能力 |
| **Clean**（清潔） | 洗う・整える | 泉、流水 | 見た目の品位・希少進化の前提 |

### 5.4 設置物が3つの役割を兼ねる（統合の要）

**ひとつの設置物を、環境属性・環境ケア・能動ケアの3つに同時に作用させる。**
これが二層モデルを「2つのメニュー」ではなく「一つの世界」として成立させる鍵である。

| 設置物 | 環境属性（§4） | 環境ケア（受動） | 能動ケア（直接操作） |
|---|---|---|---|
| 泉 | Humidity ↑ | Clean ベースライン ↑ | 触れて洗ってあげる |
| 餌箱 | Nature ↑ | Nourish ベースライン ↑ | 特別な餌を手渡す |
| 遊具 | Space ↑ | Play ベースライン ↑ | 一緒に遊ぶ |
| 寝床 | Light ↓ | Rest ベースライン ↑ | 寝かしつける |
| 発光鉱石 | Light ↑ / Mineral ↑ | — | — |

設置物を1つ置くだけで最大3つの意味が発生するため、
**仕組みの数を増やさずに深さだけを増やせる**。プレイヤーの体験としても
「メニューを開いて世話する」ではなく「世話ができる住処を整える」になる。

### 5.5 相反進化（Contrary Evolution）

> **環境の傾向と能動ケアが逆方向のとき、特殊な進化が発生する。**

静かな巣で毎日 Play 漬けにする、溶岩の巣で氷の性質を伸ばす —
**環境と世話が矛盾しているとき、そこでしか生まれないものが出る。**

- コミュニティが探索するタイプの発見要素であり、攻略動画・Wikiが量産される
- 実装コストはほぼゼロ（進化判定式に条件を1つ追加するのみ）
- 「環境で決まる」を裏切れる余地を残すことで、環境が運命ではなく**素材**になる

### 5.6 能動ケアの操作形式

**3D操作を主、メニューを補助とする。**

Roblox は3Dソーシャルプラットフォームであり、体を使ったやりとりが本来の表現である。
餌を持って運ぶ、ボールを投げる、抱き上げる — この形式の方が愛着が生まれ、
かつ**動画クリップとして強い**（§8.3 に直結）。

ただし §2 の通り、想定プレイスタイルは1日2回×5〜10分である。
**世話を作業にしてはならない。**

| 原則 | 実装 |
|---|---|
| 3D操作は「気持ちいいが短い」 | 1アクション10〜20秒。連打や長時間の拘束を課さない |
| 一括ケアのメニュー経路を常設 | 時間がない日でも完結できる。**無課金で利用可能** |
| Auto-Care（Game Pass）の位置づけ | 補助経路の自動化。面倒の回避ではなく選択肢の追加として設計する |

### 5.7 進化分岐の例

4軸の**累積実測値のバランス**で進化先が決まる。種が同じでも進化先は分岐する。

| 育成傾向 | 進化系統 | 特徴 |
|---|---|---|
| Play 偏重 × Rest 低 | Swift 系 | 高速・小型・採集速度型 |
| Nourish 高 × Rest 高 | Titan 系 | 大型・低速・採集総量型 |
| Clean 高 × 全軸均衡 | Harmony 系 | 稀少。全能力中庸だが専用外見 |
| 極端な偏り（1軸のみ突出） | Wild 系 | 個性的な外見。ネタ枠として拡散しやすい |
| **環境傾向と能動ケアが逆行** | **Contrary 系** | **最稀少。§5.5 の相反進化** |
| 全軸低位のまま放置 | **まどろみ**（Dozing） | **死なない**。眠るだけで、世話を再開すれば元に戻る |

> **設計判断**: ペットは死なせない。
> 子ども向けプラットフォームにおける喪失体験への配慮であり、
> 同時に既存の携帯型育成玩具の象徴的な仕組みとの距離を取る意図もある（§10参照）。
> 環境ケアのベースライン機構により、放置しても「まどろみ」止まりで回復できる。

### 5.8 区画（ゾーン）

種が増えると、それぞれが求める環境が異なってくる。氷系と炎系は同じ区画で
最適化できない。結果として：

> 「巣エリアを区切って種ごとに最適な環境をつくりたい」→「場所が足りない」

という欲求が**プレイヤー自身の望みとして自然に生まれる**。
Plot Expansion（§7.1）はこの欲求に応える形になり、煽って売る必要がない。
§7.2 の健全性原則に沿った、最も理想的な購買動機である。

## 6. 放置進行

ペットはオフライン中も素材と Bonds（ゲーム内通貨）を生成する。
**ケア状態が良好なほど、また環境が種に適しているほど効率が上がる。**

```
放置収益 = ペット基礎値
         × ケア状態係数(0.5〜2.0)
         × 環境適合係数(0.5〜1.5)   ← 巣がその種に合っているか
         × 進化段階倍率
         × 育成枠数
```

環境適合係数により、「その子に合った巣をつくる」という巣づくりの第二の動機が生まれる。
コレクションが増えるほど、種ごとに最適化した区画をつくりたくなる。

### 7.2 健全性の設計原則

収益性と健全性はトレードオフではない。長期運営されている
Roblox タイトルはいずれも略奪的でない設計を採用している。

| 原則 | 具体的な実装 |
|---|---|
| **Pay-to-Win を作らない** | 課金対象は「時短」「見た目」「空間」「枠」に限定。能力を直接売らない |
| **無課金で全到達可能** | すべての種・進化系統は無課金で到達できる。差は所要時間のみ |
| **確率の明示** | 卵のレアリティ確率をゲーム内で常時開示 |
| **射幸性の抑制** | 連続ガチャ演出・敗北演出を用いない。天井（一定回数で確定）を設置 |
| **選択肢を奪わない** | 課金しないことによるペナルティを設けない。進行が止まる設計にしない |
| **年齢への配慮** | 支出を煽る通知を送らない。カウントダウン型の購入圧を用いない |

> この原則は倫理面の要請であると同時に、
> プラットフォームのポリシー変更・各国の課金規制強化に対する
> 事業リスクヘッジでもある。

## 8. 継続と拡散

### 8.1 リテンション

- **デイリーケア枠**: 1日2回（朝／夜）。過度な拘束を避け、逃した場合のペナルティも設けない
- **7日連続ログイン**: 確定レア卵。ただし途切れてもリセットせず累積式にする
- **図鑑（Bondex）**: 種 × 進化系統のマトリクス。長期目標として機能
- **環境レシピの発見**: 未発見の属性組み合わせを見つけると図鑑に記録される
- **週次イベント**: 限定バイオーム素材・限定種。運営継続の中核

### 8.2 ソーシャルとトレード経済

プレイヤー間取引は、運営が手を入れなくても自律的にリテンションを生む
（Adopt Me! の本質はここにある）。

- サーバー内・サーバー跨ぎのペットトレード
- トレードは **サーバー権威型**。確認ダイアログ二段階＋全取引ログ保存
- スキャム対策：取引確定前の10秒クールダウン、内容変更時の再確認リセット
- **巣の訪問機能**: 他プレイヤーの巣を見学できる。見せびらかしたい気持ちに応える
- 「育成証明」メタデータをペットに付与（どの環境で孵り、どの傾向で育ったか）
  → 育成者の評判が価値になる二次的な経済圏

### 8.3 拡散設計

Roblox における成長は SNS 拡散に強く依存する。以下を**意図的に設計へ組み込む**。

| 仕掛け | 狙い |
|---|---|
| 孵化演出（レアリティ別カットイン） | 最も再生されるクリップ形式 |
| **進化の瞬間** | 育て方の答え合わせ。本作固有の見せ場 |
| **巣の全景ショット** | 空間づくり系のスクリーンショットはRobloxで最も拡散する |
| 進化結果カード | スクリーンショット映えする定型フォーマット |
| 「同じ卵・違う結果」比較 | 育成軸の拡散フォーマット |
| 「この巣で何が孵る？」 | 環境軸の拡散フォーマット。攻略動画が自然発生する |
| レア種発見の全体アナウンス | サーバー内の羨望を可視化 |

## 9. 名称とブランド構造

### 9.1 三層に分ける理由

名称を3層に分ける狙いは、**捨てられるものと守るべきものを分離する**ことにある。

| 層 | 名前 | 性質 | 役割 |
|---|---|---|---|
| ゲームタイトル | **Build a Biome** | **使い捨て可** | 検索とフィードでの発見。クローンの発生や流行の変化に応じて改名してよい |
| フランチャイズ | **Bondlings**（生き物の総称） | **資産** | 続編・派生を跨いで残る。商標を取るのはここ |
| スタジオ | 未定（Robloxグループ） | 資産 | 複数のフランチャイズを載せる器 |

Roblox は実験名をいつでも変更できる。**タイトルは戦術、フランチャイズは戦略**であり、
この2つを混同しないことが要点である。

### 9.2 ゲームタイトル：Build a Biome

§1.2 の通り `Hatch a X` `Egg` 系の名前空間は既存タイトルに占有されており、
そこで検索流入を取りに行くと、獲得した流入がそのまま競合の下位表示へ流れる。
差別化要素である環境（Biome）を主役に据え、**自分が検索語になる**方を狙う。

| 評価軸 | 判定 |
|---|---|
| 飽和回避 | ◎ `Build a X` は `Hatch a X` ほど混雑していない |
| 差別化の明示 | ◎ 環境をつくるゲームであることが名前で伝わる |
| 長さ | ◎ 13文字。UI上で省略されない |
| 綴りやすさ | △ biome の綴りは主要年齢層にはやや難。ロゴとアイコンで補う |

### 9.3 ゲームアイコン（最重要）

この層で最も効くのは短縮呼称ではなく、**512px四方のゲームアイコン**である。
フィードで最初に見られ、しかも極小で表示される。

> **禁止事項：アイコンにかわいいペットの顔を置かない。**

§1.2 の通り競合は全員それをやっている。同じ絵にした時点で
「Hatch a Pet の一種」に分類され、差別化は外から見えなくなる。

| 案 | 内容 | 評価 |
|---|---|---|
| **バイオームのジオラマキューブ** | 断面の見える環境の立方体（溶岩層・水層・光る鉱石）＋中央に卵 | 競合のペット顔アイコン群の中で形が違うため目に留まる。環境をつくるゲームだと一目で伝わる |
| **同じ卵・違う環境・違う結果の2分割** | 縦割りで左に溶岩＋炎の生き物、右に氷＋氷の生き物、中央に同じ卵 | 本作の全内容が絵1枚で説明される。極小表示で成立するかは要検証 |

ロゴ（ワードマーク）は `BUILD A BIOME` の横組みとする。
**アイコンには文字を入れない**（小さすぎて読めない）。

### 9.4 コミュニティ呼称：発明せず、観測して追認する

短縮形を運営側で決めてはならない。コミュニティは必ず自分たちで略すため、
公式が別の呼称を押し付けると浮く。

| 予想される呼ばれ方 | 根拠 |
|---|---|
| **"Biome"** | 最有力。`Grow a Garden` → "Garden" と同じ縮み方 |
| "BaB" / "BAB" | 打鍵用の頭字語。`BABFT` の前例あり |

**やること**: ロゴを `BUILD A **BIOME**` のように後半を強調してデザインし、
"Biome" 呼びへ自然に誘導する。公開後2〜3週間 Discord とコメント欄を観測し、
多数派を公式呼称として採用する。

### 9.5 フランチャイズ名：生き物の総称にする

**フランチャイズ名をスタジオ名ではなく「生き物の総称」に置く。**

| 層 | 一般的な構造 | 本作 |
|---|---|---|
| 個別タイトル | シリーズ第1作のタイトル | Build a Biome |
| 生き物の総称＝フランチャイズ | 生き物の総称 | **Bondlings** |
| 会社 | 開発会社名 | 未定 |

この構造には4つの利点がある。

- **プレイヤーが日常的に口にする** —「レアな Bondling が孵った」。呼ばせるための努力が要らない
- **続編を跨いで残る** — `Build a Biome 2`、`Bondlings: Deep Sea`、どちらでも生きる
- **造語なので商標が強い**（§9.6）
- **タイトルを捨てても資産が残る** — Build a Biome が埋没しても Bondlings は無傷

検討した候補と判定：

| 候補 | 判定 |
|---|---|
| **Bondlings** | ◎ 採用。造語。世話と愛着というテーマに合う |
| Kindlings | ○ 造語寄りだが kindling（焚き付け）と衝突する |
| Nestlings | ✕ 実在の英単語（雛鳥）で識別力が弱い。著名食品ブランドとの紛らわしさも懸念 |
| Broodlings | ✕ 昆虫的で不穏。既存ゲームでの使用例がある |
| Biomon | ✕ 既存の著名な生き物収集フランチャイズの派生に見える。商標リスクが高い |

`Bond` は既存商標の多い語であるため、事前調査は必須（§9.7）。

### 9.6 商標：ゲームタイトルは出願しない

**出願対象は Build a Biome ではなく Bondlings とする。** 理由は2つある。

| 理由 | 内容 |
|---|---|
| **記述的である** | build（動詞）＋ biome（対象）でゲーム内容をそのまま説明している。記述的な商標は原則として登録できない（商標法3条1項3号） |
| **単一著作物のタイトルである** | 米国では単一の創作物のタイトルは原則として商標登録が認められない（シリーズ化していれば別）。日本でも同様の論点がある |

Bondlings は造語で識別力が強く、複数作品を跨ぐ出所表示として機能するため、
この2つの障害を回避できる。

**区分（日本）**

| 区分 | 内容 |
|---|---|
| 第9類 | ダウンロード可能なゲームソフトウェア |
| 第41類 | オンラインでのゲーム提供、娯楽サービス |

**概算費用（1区分・日本）**

| 項目 | 金額 |
|---|---|
| 出願料 | 約12,000円 |
| 登録料（10年） | 約32,900円 |
| 弁理士費用 | 10〜20万円程度 |

料金表は改定されるため、実額は特許庁または弁理士に確認すること。
本節は一般的な整理であり、法的助言ではない。

### 9.7 実行順序：支出のタイミング

**商標出願を Phase 0 の前におこなってはならない。**
まだ成立するか分かっていないものに数十万円を払うことになる。

| 時期 | やること | 費用 |
|---|---|---|
| **即時** | Roblox グループ名の確保 | 100 Robux |
| **即時** | SNSハンドルの確保（Discord / TikTok / YouTube / X） | 無料 |
| **即時** | Bondlings の商標予備調査（J-PlatPat で自力検索できる） | 無料 |
| Phase 0 完了後 | 成立すると判断できた段階で弁理士に相談 | 相談料 |
| Phase 1〜2 | 手応えが確認できた段階で出願 | §9.6 の概算 |

無料・安価なものは即日押さえ、数十万円かかるものは Phase 0 の判定を待つ。
この順序なら企画が中止になっても、損失は Robux 100 と手間のみで済む。

### 9.8 スタジオ名（Robloxグループ）

Roblox ではグループが実質的なスタジオであり、実験を所有し収益を受け取る。

- ゲーム名ともフランチャイズ名とも別にする（複数のフランチャイズを載せる器のため）
- 短く、綴りやすい
- Roblox 内で一意（**先着順**）

グループ作成は 100 Robux。名前は先着のため、§9.7 の通り即時確保する。

## 10. 法務・権利チェックリスト

### 10.1 前提となる法的理解

ゲームの**ルールや仕組みはアイデアであり著作権で保護されない**
（釣りゲータウン2事件・知財高裁 2012年、2013年確定）。
「卵から孵る」「世話をする」「環境で出現種が変わる」「ブロックを置いて空間をつくる」
といった仕組み自体に法的問題はない。保護されるのは具体的な表現である。

ブロック建築については Roblox 上にも Islands、Lumber Tycoon 等の先行例が多数あり、
プラットフォーム上で確立されたジャンルである。

### 10.2 遵守事項

| 区分 | ルール |
|---|---|
| **命名** | 既存の携帯型育成玩具ブランドの名称・その語尾を模した命名を使用しない。またブロック建築ゲームの著名タイトル名および "-craft" 系の語を使用しない |
| **キャラクター** | 完全オリジナルデザイン。既存キャラの参照素材を制作フローに入れない |
| **ペット造形** | 著名ブロック建築ゲームの固有クリーチャー（緑の柱状体、長身の黒い人型 等）を想起させる造形を避ける |
| **人型造形** | 角ばった直方体の人型キャラクターを模さない |
| **テクスチャ** | **16×16ピクセルの土・草ブロック質感を再現しない**。当該テクスチャは象徴的であり著作権保護の対象 |
| **ビジュアル全般** | 卵型3ボタン筐体UI・モノクロドット絵の再現をおこなわない。独自のアートスタイルを確立する |
| **音源** | 自作またはライセンス取得済みのもののみ使用 |
| **宣伝文言** | 既存ブランド名を用いた比較訴求をおこなわない |

**決定済み名称の適合確認**

| 名称 | 判定 |
|---|---|
| **Build a Biome** | ○ 育成玩具ブランドの語尾を含まず、"-craft" 系でもない。`Build a X` は Roblox 上で複数のスタジオが用いる一般的な構文であり、特定タイトルの模倣にあたらない |

### 10.4 立方体グリッドの扱い

立方体ブロックを格子状に配置するという**仕組み**は保護されない。
問題になるのは**見た目を借りること**である。この線引きを守る限り、
ブロック状の設置物を採用すること自体にリスクはない。アートスタイルは意図的に
独自方向（例：柔らかい有機的フォルム、ピクセルでないマテリアル表現）へ振る。

### 10.5 プラットフォームリスク

Roblox は 2024年3月に **Rights Manager** を導入しており、権利者による削除申立てが可能。
DMCA 申立てを受けた場合：

- ゲームが即時削除される（異議申立ては可能だが復旧に時間を要する）
- 繰り返すとアカウント自体が終了（repeat infringer policy）
- 蓄積した収益基盤とプレイヤーがすべて失われる

**訴訟リスクよりも、プラットフォーム側の一存で事業が消えるリスクの方が実務上は深刻。**

### 10.6 推奨アクション

1. ゲーム名とキーアートが確定した段階で、知財専門弁護士による事前クリアランスを受ける
2. 自ゲーム名の商標出願を検討する（他者による先取りの回避）
3. 参照すべきモデルは既存の他社製品ではなく、
   **Roblox 上で成功している Adopt Me! / Pet Simulator / Bloxburg の設計思想**とする

## 11. 技術構成

| 領域 | 方針 |
|---|---|
| 言語 / 環境 | Luau / Roblox Studio |
| データ永続化 | ProfileService 相当（セッションロック必須。データ消失は致命的） |
| **巣データ** | 事前定義アセットIDとグリッド座標の配列として保存。ジオメトリそのものは保存しない。24×24 で 1キー4MB 制限内に十分収まる |
| **属性算出** | サーバー側でバッチ計算。設置ごとの逐次再計算はおこなわず、確定時にまとめて評価 |
| **ケアのベースライン／ドリフト** | 環境属性から算出したベースラインを巣エリア単位でキャッシュし、巣の変更時のみ再計算。ケア値のドリフトは実時間の差分から遅延評価する（毎フレーム更新やタイマー常駐はおこなわない） |
| **オフライン期間の扱い** | ログイン時に前回時刻との差分からドリフト後の値を一括算出。オフライン中の常駐処理は不要 |
| 権威モデル | **完全サーバー権威**。ケア処理・孵化抽選・進化判定・属性算出・通貨増減はすべてサーバー側 |
| 乱数 | 孵化抽選の乱数生成はサーバーのみ。クライアントに抽選結果を先渡ししない |
| クロスサーバー | MemoryStoreService（トレードキュー・グローバルイベント） |
| 負荷対策 | StreamingEnabled、巣エリアのパート数上限、ペット描画のLOD、放置演算はバッチ処理 |
| 不正対策 | クライアント入力は全て検証。配置座標の妥当性チェック。異常値検出ログ。リモートイベントのレート制限 |

## 14. 将来の拡張候補（Phase 3 以降）

本節は**現時点の設計に含まれないもの**を記録する場所である。
良い着想を捨てずに残しつつ、§4.3 のスコープ制約を守るために本編から分離している。
**Phase 0〜2 では一切実装しない。**

### 14.1 系譜（血統）

巣を使い捨てにせず生息環境として持続させる以上（§3.3）、
「そこで家族が形成され、親から子へ受け継がれていく」という発展は自然な延長線上にある。

**ただし素朴に実装すると、本作の中核と衝突する。**

親の遺伝子が子の種を決める仕組みにすると、「何が生まれるか」を決める要因が
**環境と血統の2つになり、互いに主導権を奪い合う**。§1.3 の差別化が薄まる。

**衝突を避ける設計方針：系譜を「環境の記録」にする**

| 原則 | 内容 |
|---|---|
| 種を決めるのは、あくまで**今の環境** | ここは絶対に譲らない。血統は種を決めない |
| 血統が持つのは**素質** | 親が育った環境の傾向が、子に薄く蓄積する |
| 素質の効き方は**先鋭化** | 同じ環境でも、その環境で代を重ねた血統ほど極端な結果が出やすくなる |

この形なら、**血統は中核と競合せず、中核を増幅する**。

そして最も強い所有価値が生まれる。「この子は5世代ずっと溶岩環境で育て続けた血統だ」
— これは買えず、時間をかけた者にしかつくれない。
§1.5 の「希少性が手間に由来する」を最も先鋭化した形である。

**実装を後回しにする理由**

| 理由 | 内容 |
|---|---|
| スコープ | 親の組み合わせ、素質の継承、世代管理、系譜UI。単独で1機能群になる |
| 前提条件 | 中核（環境→種）が体感として成立していることが前提。Phase 0 の判定前に着手する意味がない |
| 年齢層への配慮 | 繁殖の表現は子ども向けプラットフォームでは慎重な扱いを要する。「巣に新しい卵が増える」程度の抽象度に留める設計が必要 |

**着手の条件**: Phase 2 のソフトローンチでリテンションが目標に届き、
かつプレイヤーが自発的に「同じ環境で育て続ける」行動を取っていることが
観測できた場合に限り、Phase 3 の候補として再検討する。

## 付録A. 用語の定義

本書は用語を以下に統一する。**巣は「建てる」ものではなく「つくる」もの**であり、
建築・家屋を想起させる語は、他社ゲームのジャンルを指す場合を除いて用いない。

### 空間まわり

| 用語 | 意味 | 使わない語 |
|---|---|---|
| **巣** | ペットが生まれ、暮らす場所の全体 | 家、ハウス |
| **巣エリア** | 固定サイズのグリッド（24×24 等）。設置物を置ける範囲 | プロット、敷地 |
| **区画（ゾーン）** | 巣エリアを分割した、種ごとに最適化する小領域 | — |
| **巣づくり** | 巣エリアに設置物を置いて環境をつくる遊び全体 | 建築、ビルド |
| **設置物** | 巣エリアに置くオブジェクト（地形タイル・装飾物・ケア用具） | 建築オブジェクト、配置物、プロップ |
| **素材** | 採集して集める資源。設置物の作成に使う | — |
| **環境属性** | 設置物から算出される6つの値（Heat / Humidity / Light / Nature / Mineral / Space） | — |

**動詞の統一**

- 巣を **つくる / 整える / 育てる**。設置物を **置く**
- 「建てる」「建築する」は用いない（家屋を想起させるため）
- **「飾る」も用いない** — 本作の設置物は見た目だけでなく機能を持つため、
  装飾を意味する語では実態と合わない
- **「巣を育てる」は体験を語るときの正式な表現**とする（§2、宣伝文で使用）。
  一度つくって終わりではなく継続的に手を入れるという §3.3 の設計を、
  語彙のレベルで表している。ペットの「育成」と同じ動詞を使うことで、
  「プレイヤーの選択が生命を形作る」というテーマ（§1.6）が語彙上も統一される。
  ただし巣にレベルや経験値の仕組みがあるという意味ではない

### 名称まわり

| 用語 | 意味 |
|---|---|
| **Build a Biome** | ゲームタイトル。Roblox 上の実験名。発見のための名前であり、必要なら改名してよい（§9.1） |
| **Bondlings** | 生き物の総称であり、フランチャイズ名。商標出願の対象。続編を跨いで残る資産（§9.5） |
| **"Biome"** | コミュニティでの想定短縮呼称（§9.4）。環境属性としての「バイオーム」とは文脈で区別する |

### 育成まわり

| 用語 | 意味 |
|---|---|
| **世話** | プレイヤーがペットに直接おこなう行為（散文ではこちらを使う） |
| **ケア** | 世話を数値として扱うときの仕組み上の呼称（ケアパラメータ、能動ケア、環境ケア） |
| **能動ケア** | プレイヤーの操作によるケア |
| **環境ケア** | 巣の環境が継続的に供給するケア |
| **ベースライン** | 環境ケアが定める各ケア軸の均衡点 |
| **ドリフト** | ケア値が時間とともにベースラインへ戻っていく挙動 |
| **まどろみ（Dozing）** | ケア値が全軸低位のまま放置された状態。死亡ではなく、世話再開で回復する |
| **相反進化（Contrary Evolution）** | 環境の傾向と能動ケアが逆方向のときに発生する特殊進化 |

### 表記ルール

- 系統名（Swift / Titan / Harmony / Wild / Contrary）と商品名（Plot Expansion 等）は英語表記のまま。ゲーム内表示が英語のため
- 「スクリーンショット」と表記する（「スクショ」を用いない）
- 日本語の文中に生の英単語を混ぜない（density → 密度、build → つくったもの）
- 改訂の経緯を本文に書かない（「〜の追加により」等）。本文は常に完成形として読めるようにする
