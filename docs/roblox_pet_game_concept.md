# 仮想ペット育成ゲーム 企画概要（Roblox）

- **仮称**: Bondlings — Hatch & Raise
- **プラットフォーム**: Roblox（Luau / Roblox Studio）
- **ジャンル**: 仮想ペット育成 × 放置進行（Virtual Pet Raising / Idle Progression）
- **作成日**: 2026-09-05
- **ステータス**: 企画段階（未着手）

---

## 1. コンセプト

> **同じ卵から、あなたの育て方だけの一匹が生まれる。**

卵を孵し、世話をして育てる。ここまでは既存の仮想ペット育成と同じ。
本作の中核は **「世話の質と傾向が、進化先を決定する」** という一点にある。

既存のRoblox上のペット系タイトル（Adopt Me!、Pet Simulator 系）では、ペットは
**抽選で決まる静的な戦利品**である。レアリティはRNGが決め、プレイヤーの行動は結果に影響しない。

本作ではペットの最終形態を **プレイヤーの行動の関数**とする。
同じ卵を配っても、育て方が違えば別の姿になる。これにより：

| 効果 | 内容 |
|---|---|
| 唯一性 | 「自分だけのペット」が構造的に生まれる |
| 見せびらかし価値 | レアリティではなく「育成の証明」が自慢になる |
| トレード価値 | 希少性がRNGではなく**手間**に由来するため、価値が安定する |
| 継続動機 | 世話しないと理想の進化に到達しないため、毎日戻る理由がある |
| 拡散性 | 「同じ卵からこんなに違う」という比較がSNSで機能する |

## 3. コアループ

### 3層構造

```
[Micro / 30秒〜2分]
  世話アクション（餌・遊び・休息・清掃）
    → ケアパラメータ変動
    → 即時フィードバック（表情・アニメーション・エフェクト）

[Meso / 1日]
  卵の孵化 → デイリー任務 → 放置収益の回収 → 進化判定
    → 進化の瞬間（本作最大の見せ場）

[Macro / 1週間〜]
  レア卵の入手 → 進化ツリーの踏破 → トレード → 図鑑コンプリート
```

### ケアパラメータ（4軸）

| 軸 | 上げる行動 | 系統への影響 |
|---|---|---|
| **Nourish**（栄養） | 餌やり・特殊フード | 体格・耐久 |
| **Play**（遊び） | ミニゲーム・散歩 | 俊敏・活発さ |
| **Rest**（休息） | 寝かせる・静かな環境 | 落ち着き・特殊能力 |
| **Clean**（清潔） | 洗う・整える | 見た目の品位・希少進化の前提 |

### 進化分岐の例

4軸の**累積バランス**で進化先が決まる。

| 育成傾向 | 進化系統 | 特徴 |
|---|---|---|
| Play 偏重 × Rest 低 | Swift 系 | 高速・小型・放置収益の速度型 |
| Nourish 高 × Rest 高 | Titan 系 | 大型・低速・放置収益の総量型 |
| Clean 高 × 全軸均衡 | Harmony 系 | 稀少。全能力中庸だが専用外見 |
| 極端な偏り（1軸のみ突出） | Wild 系 | 個性的な外見。ネタ枠として拡散しやすい |
| 全軸低位のまま放置 | Dozing 状態 | **死亡しない**。眠るだけで、世話再開で復帰可能 |

> **設計判断**: ペットは死亡させない。
> 子ども向けプラットフォームにおける喪失体験への配慮であり、
> 同時に既存の携帯型育成玩具の象徴的機構との距離を取る意図もある（§8参照）。

### 放置進行（Idle Layer）

ペットはオフライン中もリソース（Bonds＝ゲーム内通貨）を生成する。
**ケア状態が良好なほど生成効率が上がる**ため、「世話する経済的理由」が成立する。

```
放置収益 = ペット基礎値 × ケア状態係数(0.5〜2.0) × 進化段階倍率 × 育成枠数
```

これにより、農場シミュレーターの持つ「戻ってくる理由」を
ペット育成の情緒的動機と接続する。

### 4.1 課金カテゴリ

| Auto-Care | 399 Robux | 一定時間の自動世話（ケア状態の維持） |
| Double Bonds | 299 Robux | 放置収益 2倍 |
| VIP Nest | 599 Robux | 専用エリア＋限定装飾＋デイリー報酬増 |

**Developer Product（消費型）**

| 商品 | 想定価格 | 内容 |
|---|---|---|
| Premium Egg | 49〜99 Robux | 高レアリティ出現率が高い卵 |
| Growth Accelerator | 29 Robux | 孵化・成長の時間短縮 |
| Care Kit | 19 Robux | ケアパラメータ回復セット |
| Trade Slot Expansion | 99 Robux | 同時トレード枠の拡張 |

**シーズン限定**

- 期間限定卵（期間終了後は入手不可 → 希少性が永続的に維持される）
- イベント限定進化系統
- シーズンパス（無料トラック＋有料トラックの二層構成）

### 4.2 健全性の設計原則

収益性と健全性はトレードオフではない。長期運営されている
Roblox タイトルはいずれも非略奪的な設計を採用している。

| 原則 | 具体的な実装 |
|---|---|
| **Pay-to-Win を作らない** | 課金対象は「時短」「見た目」「枠」に限定。能力を直接売らない |
| **無課金で全到達可能** | すべての進化系統は無課金で到達できる。差は所要時間のみ |
| **確率の明示** | 卵のレアリティ確率をゲーム内で常時開示 |
| **射幸性の抑制** | 連続ガチャ演出・敗北演出を用いない。天井（一定回数で確定）を設置 |
| **選択肢を奪わない** | 課金しないことによるペナルティを設けない。進行が止まる設計にしない |
| **年齢への配慮** | 支出を煽る通知を送らない。カウントダウン型の購入圧を用いない |

> この原則は倫理面の要請であると同時に、
> プラットフォームのポリシー変更・各国の課金規制強化に対する
> 事業リスクヘッジでもある。

## 5. リテンション設計

- **デイリーケア枠**: 1日2回（朝／夜）。過度な拘束を避け、逃した場合のペナルティも設けない
- **7日連続ログイン**: 確定レア卵。ただし途切れてもリセットせず累積式にする
- **図鑑（Bondex）**: 進化系統のコンプリート要素。長期目標として機能
- **週次イベント**: 限定卵・限定環境。運営継続の中核
- **トレード経済**: プレイヤー間取引が自律的にリテンションを生む（Adopt Me! の本質）

---

## 6. ソーシャル／トレード経済

- サーバー内・サーバー跨ぎのペットトレード
- トレードは **サーバー権威型**。確認ダイアログ二段階＋全取引ログ保存
- スキャム対策：取引確定前の10秒クールダウン、内容変更時の再確認リセット
- 「育成証明」メタデータをペットに付与（誰が・どの傾向で育てたか）
  → 育成者の評判が価値になる二次的な経済圏

## 8. 法務・権利チェックリスト

### 前提となる法的理解

ゲームの**ルールやシステムはアイデアであり著作権で保護されない**
（釣りゲータウン2事件・知財高裁 2012年、2013年確定）。
「卵から孵る」「世話をする」「育て方で進化が変わる」という仕組み自体に
法的問題はない。保護されるのは具体的な表現である。

### 遵守事項

| 区分 | ルール |
|---|---|
| **命名** | 既存の携帯型育成玩具ブランドの名称・その語尾を模した命名を一切使用しない。ゲーム名・説明文・タグ・SNS 投稿すべてに適用 |
| **キャラクター** | 完全オリジナルデザイン。既存キャラの参照素材を制作フローに入れない |
| **ビジュアル** | 卵型3ボタン筐体UI・モノクロドット絵の再現を行わない。Roblox 3D 表現で独自のアートスタイルを確立 |
| **音源** | 自作またはライセンス取得済みのもののみ使用 |
| **宣伝文言** | 既存ブランド名を用いた比較訴求を行わない |

### 宣伝文句の置換表

| ✕ 使用禁止 | ○ 使用する |
|---|---|
| （既存ブランド名）風 | virtual pet / 仮想ペット育成 |
| （既存ブランド名）ライク | egg hatching / pet raising |
| （既存ブランド名）の3D版 | care-based evolution |

> **重要**: 本ドキュメント内および開発チーム内での既存製品への言及は
> 設計上の参照に留め、**公開されるいかなるテキストにも残さないこと**。

### プラットフォームリスク

Roblox は 2024年3月に **Rights Manager** を導入しており、
権利者による削除申立てが可能。DMCA 申立てを受けた場合：

- ゲームが即時削除される（異議申立ては可能だが復旧に時間を要する）
- 繰り返すとアカウント自体が終了（repeat infringer policy）
- 蓄積した収益基盤とプレイヤーがすべて失われる

**訴訟リスクよりもプラットフォーム側の一存で事業が消えるリスクの方が実務上は深刻。**

### 推奨アクション

1. ゲーム名とキーアートが確定した段階で、知財専門弁護士による事前クリアランスを受ける
2. 自ゲーム名の商標出願を検討する（他者による先取りの回避）
3. 参照すべきモデルは既存の携帯型育成玩具ではなく、
   **Roblox 上で成功している Adopt Me! / Pet Simulator の設計思想**とする

## 9. 技術構成

| 領域 | 方針 |
|---|---|
| 言語 / 環境 | Luau / Roblox Studio |
| データ永続化 | ProfileService 相当（セッションロック必須。データ消失は致命的） |
| 権威モデル | **完全サーバー権威**。ケア処理・孵化抽選・進化判定・通貨増減はすべてサーバー側 |
| 乱数 | 孵化抽選の乱数生成はサーバーのみ。クライアントに抽選結果を先渡ししない |
| クロスサーバー | MemoryStoreService（トレードキュー・グローバルイベント） |
| 負荷対策 | StreamingEnabled、ペット描画のLOD、放置演算はバッチ処理 |
| 不正対策 | クライアント入力は全て検証。異常値検出ログ。リモートイベントのレート制限 |

## 11. リスクと対応

| リスク | 深刻度 | 対応 |
|---|---|---|
| ジャンル飽和による埋没 | 高 | 「進化分岐」という単一の強い差別化に集中する。機能を増やして薄めない |
| 初動での露出獲得失敗 | 高 | ローンチ前にクリエイター配布・事前コミュニティ形成を行う |
| 運営継続コスト | 中 | 週次更新の自動化基盤（イベント設定のデータ駆動化）を Phase 1 で作る |
| 自分がクローンされる側になる | 中 | メカニクスは模倣される前提。運営速度とコミュニティで差をつける |
| データ消失事故 | 高 | セッションロック必須。バックアップとロールバック手順を Phase 1 で確立 |
| 収益の超上位集中 | — | 中央値の収益はほぼゼロという前提で事業計画を立てる。撤退基準を事前に決める |
